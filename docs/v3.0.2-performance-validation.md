# ATHLTH 3.0.2 — Performance acceptance checklist

Use the same device, OS, Release configuration, account and representative
dataset before and after a change. Record both cold and warm runs. Do not
treat a simulator smoke test as a measured device performance improvement.

## Instruments

Record Time Profiler, SwiftUI, Core Animation and Allocations on iPhone and
iPad. Use the existing Performance signpost category. New intervals:
PlanCatalogFilter, PlanDraftCheckpoint, WorkoutDraftCheckpoint,
WorkoutDurationProjection, ProgressPeriodProjection. Existing Home, Health
and route thumbnail intervals remain enabled.

## Acceptance scenarios

| Scenario | Proposed warm target | Functional check |
| --- | --- | --- |
| Home to Train and back, 10 repetitions | first interactive frame under 200 ms | no navigation reset or stale account data |
| Open a loaded workout | under 150 ms | full recipe, all targets and groups intact |
| Basic/Advanced switch | under 100 ms | no lost steps or duplicate execution |
| Change an interval target | under 100 ms | correct total, checkpoint survives background/close |
| Search/filter a populated library | under 250 ms after committed search | all filters and A–Å pagination preserved |
| Scroll Home, Insights, Library, Explore | consistent device refresh cadence | no visible image or card jumps |
| Strength and running live session | no long main-thread stalls | clocks, Audio Coach, HR, Watch and live sharing remain correct |
| Reopen an existing conversation | no unnecessary full inbox fetch when unchanged | read, retraction, shared workout and request state preserved |

Record median and p95, peak resident memory and animation hitches. Repeat
with a long workout, a full year of activity, a large training plan, 300+
messages and multiple routes. Exercise account switching, offline behavior,
background/resume and accessibility sizes. Check iPhone, iPad and Apple
Watch. Compare release builds at exact commit IDs.

These are targets, not measured results. Do not reduce safety checks or
disable required refresh, recording, or recovery logic to meet them.

## Deferred structural work

Measure before migrating message polling to realtime, narrowing the full
group calendar to a requested date interval, restructuring the largest
SwiftUI views, or changing map rendering concurrency. Those changes need
dedicated functional coverage and must not hide history or change execution.

## Final performance pass: private Realtime, presence, modularization

- Direct conversations use private Broadcast topics scoped to account and thread, with an empty application payload. The server emits invalidations only for message insertion, deletion, visible receipt changes and conversation request state. The app reloads the existing authenticated view; hidden receipt-only writes do not notify the sender. No direct-message table is added to a publication.
- Keep four-second message polling when disconnected; use sixteen-second safety reconciliation while subscribed. Challenge status retains its previous eight-second cadence. APNs/resume remain additional invalidation paths. Test two accounts and two devices, read receipts on/off, retraction, requests, connection loss, account changes, and app background/foreground. Group chat is not switched to the direct-message channel.
- Applied and tracked database migrations 20261125140708 and 20261125140944. Rollback-only database tests confirmed content-free signals, no signal on unchanged hidden receipt state, visible receipt/delete signals, own-topic access and cross-account/anonymous denial. The same SQL regression is required in backend CI. Security advisor returned no finding naming the new Realtime policy/function; other pre-existing advisor findings are outside this change.
- Active workout presence heartbeat uses a 12-second minimum interval only for the same session and source; 30-second expiration and immediate source/session changes remain. Four-second metric/control loop is unchanged. Signposts: CrossDevicePresenceWrite, CrossDeviceWorkoutPublish. Verify actual iPad/Watch live progress, consent, controls, source switches, pause/resume and disconnect expiry.
- Moved direct conversation presentation (~4,420 lines), live read/presentation policies (~160 lines), and Insights session baseline model (~98 lines) into dedicated files atomically. This separates responsibilities without changing public view identifiers or layout.
- Isolated Swift 6 policy assertions: 13/13 passed (polling fallback, heartbeat interval, session/source changes, clock reversal). XCTest cases added to existing release suites.
- Physical validation is still mandatory. Use a Release build on iPhone and iPad with Instruments (Time Profiler, Allocations, SwiftUI and Animation Hitches). Compare the same account and same history before/after; record cold/warm Hjem/Train navigation, library scrolling/search, 4×4 drag changes, 90-day history, map scrolling, 10-minute chat, and 10-minute iPhone/Watch/iPad session. Report median/p95, peak memory, frame hitches and network requests. No measured device speedup is claimed yet.
