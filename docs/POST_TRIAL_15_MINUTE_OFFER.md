# ATHLTH+ one-time post-trial offer — 15-minute claim window

## Agreed UX and eligibility

- On the **first authenticated app foreground after the 7-day ATHLTH internal trial has expired**, offer an App Store code once per backend account. Close button always available.
- Display only if the account has actually finished its ATHLTH trial, has no paid StoreKit subscription, and the server has genuine available App Store Connect codes.
- **Exactly one presentation per user ID across iPhone/iPad/reinstalls.** The database keeps the original presentation even after the deadline.
- The **15-minute timer starts at first eligible presentation on server**, and cannot restart on relaunch or by adjusting the iPhone's clock.
- A user can claim an actual Apple offer code only within those 15 minutes. Reopening ATHLTH never shows the offer again.
- The 15-minute window applies to **claiming a code inside ATHLTH**. Apple, not ATHLTH, controls the code's ultimate redemption expiry and discounted billing schedule. Do not claim that a code expires at 15 minutes if Apple does not enforce that.
- ATHLTH doesn't auto-subscribe anybody or disguise auto-renewal. Apple checkout displays the final price in App Store currency.

## APP STORE CONNECT SETUP REQUIRED BEFORE LAUNCH

1. In App Store Connect choose the ATHLTH+ yearly subscription and **create a subscription offer-code campaign** explicitly eligible for **new subscribers**, because the ATHLTH in-app 7-day trial is *not* a prior App Store subscription. Configure a genuine discounted period and renewal details. Do not configure only a StoreKit promotional offer for prior subscribers.
2. Generate unique *one-time-use* codes and download the securely exported codes. Apple controls code redemption, offer price, country/region eligibility and code expiry; select the regions where ATHLTH+ is sold.
3. Import unused valid codes into Supabase `private.athlth_post_trial_offer_codes` **only through a secure SQL admin session** (never the client or GitHub). Supply `code`, matching `product_id`, and `apple_expires_at` (recommended). Codes must never be generated by the app.
4. Check that at least one available code exists and test redemption with an eligible Apple sandbox account in the correct storefront. Import no duplicate/redeemed codes.
5. Enable the Supabase Edge Function secret `ATHLTH_POST_TRIAL_OFFER_ENABLED=true` **last**. It is intentionally absent/false until configured, so no popups appear without real redeemable codes.
6. To stop presenting, set the flag false immediately; all user data and existing trial history remain unchanged.

## Infrastructure

- Migration `supabase/migrations/20261019103000_post_trial_once_15_minute_offer.sql` creates private inventory, permanent presentation ledger and private service-role-only RPCs `start_athlth_post_trial_offer` and `claim_athlth_post_trial_offer`.
- Deployed Edge Function `post-trial-offer` verifies JWT server-side before calling the RPC. The client never sends its own user ID. An expired, free, paid, revoked or non-trial account cannot mint a promotion.
- Codes are reserved only once, under a database lock. After an unclaimed 15-minute window expires, the unused code may be allocated to another account, while the original account remains permanently marked as already presented.
- Claim rechecks trial and subscription status and enforces the original deadline in SQL. Only a successful claim returns an offer code to its signed-in account.
- The app uses Apple's native code-redemption sheet. Purchases and receipt validation stay in StoreKit/ATHLTH's existing subscription architecture.

## Release testing

- Brand-new account before expiration: no offer; active trial: no offer; account with paid receipt: no offer.
- Newly expired user with code available: first foreground shows one 15-minute claim window.
- Closing/reopening or changing device/reinstalling: **never show again**, even before the initial timer has elapsed.
- No codes, disabled feature flag, database/network error: no offer; normal ATHLTH access continues.
- Eligible user claiming in time: one code is revealed and Apple offer redemption opens. Expired claim is rejected even if device clock is changed.
- Apple account in wrong storefront, existing subscriber or invalid code: Apple redemption rejects, app must not promise a purchase.
- Confirm iPhone and iPad Swift builds, backend migration tests, and physical App Store sandbox redemption before TestFlight.
