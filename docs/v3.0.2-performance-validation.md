# ATHLTH 3.0.2 — Performance acceptance checklist

Use the same device, OS, Release configuration, account and representative
dataset before and after a change. Record both cold and warm runs. Do not
treat a simulator smoke test as a measured device performance improvement.

## Instruments

Record Time Profiler, SwiftUI, Core Animation and Allocations on iPhone and
iPad. Use the existing Performance signpost category. New intervals:
PlanCatalogFilter, PlanDraftCheckpoint, WorkoutDraftCheckpoint,
WorkoutDurationProjection, ProgressPeriodProjection. Existing Home, Health
and route thumbnail intervals remain enabled.

## Acceptance scenarios

| Scenario | Proposed warm target | Functional check |
| --- | --- | --- |
| Home to Train and back, 10 repetitions | first interactive frame under 200 ms | no navigation reset or stale account data |
| Open a loaded workout | under 150 ms | full recipe, all targets and groups intact |
| Basic/Advanced switch | under 100 ms | no lost steps or duplicate execution |
| Change an interval target | under 100 ms | correct total, checkpoint survives background/close |
| Search/filter a populated library | under 250 ms after committed search | all filters and A–Å pagination preserved |
| Scroll Home, Insights, Library, Explore | consistent device refresh cadence | no visible image or card jumps |
| Strength and running live session | no long main-thread stalls | clocks, Audio Coach, HR, Watch and live sharing remain correct |
| Reopen an existing conversation | no unnecessary full inbox fetch when unchanged | read, retraction, shared workout and request state preserved |

Record median and p95, peak resident memory and animation hitches. Repeat
with a long workout, a full year of activity, a large training plan, 300+
messages and multiple routes. Exercise account switching, offline behavior,
background/resume and accessibility sizes. Check iPhone, iPad and Apple
Watch. Compare release builds at exact commit IDs.

These are targets, not measured results. Do not reduce safety checks or
disable required refresh, recording, or recovery logic to meet them.

## Deferred structural work

Measure before migrating message polling to realtime, narrowing the full
group calendar to a requested date interval, restructuring the largest
SwiftUI views, or changing map rendering concurrency. Those changes need
dedicated functional coverage and must not hide history or change execution.
