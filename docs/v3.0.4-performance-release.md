# ATHLTH 3.0.4 — performance and stability release

Baseline: 3.0.3, commit 16c0af6ea186f4019cc9380804d165d04190ce23.
Version 3.0.4 / build 144. The prior release remains on locked/v3.0.3 and backup/v3.0.3.

## Changes in this pass

- Reuse one immutable public RepDB snapshot across short-lived library stores; never share private exercise entries or search results between accounts.
- Index public exercise-equivalence candidates before projecting the selectable catalog.
- Keep a small bounded, revision-invalidated search-result memo and reuse sorted catalog order. More restrictive token queries can reuse their prior subset.
- Index session IDs per plan and invalidate on plan/account mutation; cache structured history by the actual persisted payload, not a time-to-live.
- Move root-level live-workout pills, coordinated-lobby presentation and badge observation into dedicated small SwiftUI leaves. Root reacts to the resulting badge count only rather than observing every HealthKit, message or workout telemetry publication.
- Existing recording, HealthKit, Watch, approval, privacy and draft safety policies are not relaxed.
- New signposts: ExerciseCatalogProjection, ExerciseSearchProjection, PlanSessionIndex, StructuredHistoryDecode.

## Acceptance and remaining work

Use docs/v3.0.2-performance-validation.md as baseline. Run Release builds on physical iPhone and iPad and compare cold/warm median/p95, peak memory, hitches and query counts at identical account/dataset/OS. Check Watch recording separately. The proposed targets are not measured improvements.

Review broad observation dependencies in the large root, Home, Train, active-workout, profile, messaging and community views with Instruments SwiftUI. Split high-frequency inputs from static card projections only where traces justify it. Measure image decoding, maps, media, network and database separately. No blanket debouncing or disabling background sync. Do not label this release complete until physical results and full functional regression coverage are recorded.

The build and launch/iPad smoke gates now include release/v3.0.4. No TestFlight publication is requested by this change.
