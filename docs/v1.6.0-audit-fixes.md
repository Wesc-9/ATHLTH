# ATHLTH 1.6.0 audit fixes

Based on `release/v1.6.0` at `9e367ba`, incorporating changes after the original
audit at `c8c2e70`. No other release branch is targeted.

| Finding | Change |
| --- | --- |
| Purchase product IDs differ | Both Apple Edge Functions accept the monthly/yearly IDs used by StoreKit. The verification handler also uses the documented `userClaims.id`, rather than nonexistent `sub`. |
| Workout photos have public URLs | Private bucket; Storage reads follow metadata RLS. App resolves stable locators to signed URLs, including legacy event/challenge covers. New uploads cache for 60 seconds. Image tasks are scoped to account changes. |
| Account deletion leaves stored files | Service-only inventory covers all buckets and owned objects, including shared group folders and legacy personal paths. Storage API removes successive first pages before auth deletion; failures return a retryable error. |
| Health-derived sharing defaults to public | App fallback and SQL defaults keep training sections private and sharing switches off. Existing user choices are preserved. |
| Duplicate migration versions | Applied version numbers recovered from Supabase; archive retained outside the active migration directory. |
| Missing foundational migrations | All 128 applied schema migrations recovered with a checksum manifest. |
| Backup loses edits during upload | Revision tracker leaves later edits dirty so the scheduler uploads another snapshot. |
| Previous account remains in widgets | Clear shared widget snapshot and Live Activities on sign-out/account changes. Reject queued activity updates from an earlier account generation. Clear image caches on account changes. |
| Username rules disagree | App and availability RPC use the database's ASCII `a-z`, `0-9`, underscore and 3–20-character limits. |

## Validation

- Replayed all 129 migrations in an empty local PostgreSQL 18.4 database with
  minimal Supabase platform schemas and roles. `citext` is real; `pg_net` is
  omitted in this embedded distribution. No application tables were stubbed.
- `supabase/tests/v160_audit.sql` passes for private defaults, owner/viewer photo
  access, unpublished uploads, username rules and service-only storage inventory.
- Three account-storage cleanup tests pass (235 objects, multiple buckets,
  partial failure/retry, failed inventory, and detection of stalled deletion).
- Deno typechecking passes for the three changed Edge Functions.
- Product-ID contract, 128 recovered migration checksums and 129 unique versions
  pass. `git diff --check` passes.
- iOS XCTest cases were added for privacy defaults, username rules, image
  locators and the backup race. They require Xcode and have not run locally.
  The build workflow runs them on a Mac; the new backend workflow uses the full
  disposable Supabase stack with Postgres 17.

## Deployment order

1. Run Mac build/tests and the Postgres 17 backend workflow. Test account
   switching, image uploads and Apple sandbox purchases on a device.
2. Check `supabase migration list --linked` against the recovered history. Only
   `20261004095402_v160_audit_privacy_and_account_cleanup.sql` should be pending.
   Never reset the hosted database or replay archived migrations.
3. Release the app image-loader change before making the bucket private, or
   coordinate both changes during a maintenance window. Old clients cannot load
   private photos with their original public-only loader.
4. Apply the new migration, then deploy `delete-account`,
   `verify-app-store-transaction`, and `app-store-notifications`. Keep existing
   authentication settings for each function.
5. Refresh existing objects to invalidate their old public CDN entries and
   replace the previous one-year cache headers. First run
   `deno run --allow-env=SUPABASE_URL,SUPABASE_SERVICE_ROLE_KEY --allow-net scripts/harden_workout_media_cache.ts`
   using admin credentials, then repeat with `--apply` after checking the count.
   This transfers and rewrites every object in the bucket; budget bandwidth and
   allow up to 60 seconds for CDN invalidation. Verify old public URLs fail and
   permitted signed images still load.
6. Exercise account deletion with avatar, gear, photos and group uploads;
   confirm both account removal and absence of its owned Storage files.

Changing defaults does not prove consent for existing users. Review existing
public-sharing settings and request consent in the product if necessary.
Previously downloaded browser files cannot be recalled. Already-issued signed
URLs are bearer links, and their CDN cache lifetime is independent of token
expiry. See [Supabase's cache guidance](https://supabase.com/docs/guides/storage/cdn/smart-cdn).

Production migrations, function deployment, cache refresh and App Store release
have not been performed by this change.
