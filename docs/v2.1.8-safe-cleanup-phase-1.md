# ATHLTH 2.1.8 — safe dead-code and runtime cleanup, phase 1

## Verified changes in release/v2.1.8

1. Removed the unused `horizontalItem`, `featuredItem`, and `compactItem` functions from `HomePersonalRecentActivity.swift`. Also removed six private, now-unreferenced legacy activity card views. The new vertical `verticalItem` feed, engagement interactions, profile routing, HealthKit-backed summaries and actual strength/route artwork remain intact. Source reduced by approximately 39,687 characters (~20% of this file).
2. Removed the second, redundant initial `refreshRecentWorkouts()` launch from the same Home activity view. The `onAppear` refresh (needed after returning from history) and foreground/data-change refresh paths remain in place.
3. In the weekly progress day sheet, filter running-library favorites by stored template ID before constructing full `PlannedSession` objects. No favorite record, exercise prescription or stored workout is modified.

## Scope / guarantees

- No changes to persisted models, existing workout records, HealthKit queries or consent, Supabase rows/RLS, Apple Watch capture, offline stores or training-plan calculations.
- Reducing dead source shrinks compilation work and future maintenance; it does not by itself prove better on-device frame latency. The favorites change removes avoidable object construction on each sheet render.
- Static source checks confirmed balanced braces and eliminated old private view identifiers; they are **not** an Xcode compile, XCTest run or Instruments profile.

## Next release gates

- Xcode-generated project build and `ATHLTHTests` on the exact current commit, including recent activity, weekly day sheet and library favorites.
- iPhone performance before/after: cold launch, Home→Train→Home, opening a weekly progress date, 1/100/1,000+ HealthKit workouts, rapid account switching, offline mode.
- Instruments Time Profiler and Allocations: identify duplicate scene/app-level HealthKit refresh, costly body recomputation, route-map snapshots and memory peaks. Remove additional code only after references and persisted compatibility are verified.
- Review the historical `fetchRawAllWorkouts()` unbounded HealthKit fetch noted in the 2.0.8 audit; do not change pagination semantics without tests for HealthKit deletions, duplicate import handling and permissions.
- No automatic TestFlight build or deployment was started in this cleanup.
