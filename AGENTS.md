- **iPhone / iPad plan-editor parity (2.1.3):** All structured workout building, interval/phase editing, draft restoration, exercise selection, validation, saving and plan construction must remain in the **shared** `ATHLTHTrainingPlanBuilderFlow`, `WorkoutTemplateBuilderView`, `ATHLTHPlannedWorkoutStudioView` and `AppSessionStore` paths. Add new features to these shared components first; do not fork a second iPad workout-builder engine. The iPad-only `ATHLTHStudioPlanCanvasView` and `ATHLTHStudioTrainWorkspaceView` own presentation, week navigation and responsive layout only. `athlthStudioFullscreenEditing` is true on iPad Studio; false by default on iPhone. Full-screen plan/workout construction must retain a reliable back/close path, draft recovery, and the existing save callbacks. Verify both iPhone and iPad when changing shared builders, plus narrow iPad multitasking widths. No TestFlight upload for 2.1.3 without explicit permission.
- **Adaptive iPad Plan Studio (2.1.3):** The Studio root uses a compact icon rail on the Plan Studio tab. New-plan editing (`ATHLTHTrainingPlanBuilderFlow`) and existing-plan editing (`ATHLTHStudioPlanCanvasView`) both use `ATHLTHStudioAdaptiveWorkspace` around the same shared iPhone workout editors. Default is a split with the workout editor taking roughly two-thirds of the usable width; users can drag the divider, which remembers their width, and toggle Focus Mode without leaving the plan. At narrow Stage Manager widths the editor occupies the workspace and a control toggles the plan. Never re-introduce a modal/full-screen *workout editor* for these Studio paths or fork the workout engine to implement a tablet feature. Preserve draft recovery and plan-version checks; do not silently switch an unsaved editor to a different week/day. Keep the shared iPhone experience unchanged and always run both platform builds.
