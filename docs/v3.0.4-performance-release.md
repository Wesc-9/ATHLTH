# ATHLTH 3.0.4 — performance and stability release

Baseline: 3.0.3, commit 16c0af6ea186f4019cc9380804d165d04190ce23.
Version 3.0.4 / build 144. The prior release remains on locked/v3.0.3 and backup/v3.0.3.

## Changes in this pass

- Reuse one immutable public RepDB snapshot across short-lived library stores; never share private exercise entries or search results between accounts.
- Index public exercise-equivalence candidates before projecting the selectable catalog.
- Keep a small bounded, revision-invalidated search-result memo and reuse sorted catalog order. More restrictive token queries can reuse their prior subset.
- Index session IDs per plan and invalidate on plan/account mutation; cache structured history by the actual persisted payload, not a time-to-live.
- Move root-level live-workout pills, coordinated-lobby presentation and badge observation into dedicated small SwiftUI leaves. Root reacts to the resulting badge count only rather than observing every HealthKit, message or workout telemetry publication.
- Existing recording, HealthKit, Watch, approval, privacy and draft safety policies are not relaxed.
- New signposts: ExerciseCatalogProjection, ExerciseSearchProjection, PlanSessionIndex, StructuredHistoryDecode.

## Acceptance and remaining work

Use docs/v3.0.2-performance-validation.md as baseline. Run Release builds on physical iPhone and iPad and compare cold/warm median/p95, peak memory, hitches and query counts at identical account/dataset/OS. Check Watch recording separately. The proposed targets are not measured improvements.

Review broad observation dependencies in the large root, Home, Train, active-workout, profile, messaging and community views with Instruments SwiftUI. Split high-frequency inputs from static card projections only where traces justify it. Measure image decoding, maps, media, network and database separately. No blanket debouncing or disabling background sync. Do not label this release complete until physical results and full functional regression coverage are recorded.

The build and launch/iPad smoke gates now include release/v3.0.4. No TestFlight publication is requested by this change.

## Second pass

- Reuse owner-local recorded-workout projections in iPhone Home, Train recommendations and iPad editorial Home.
- Reuse video players for the lifetime of visible exercise details and release them on dismissal.
- Skip file metadata lookups for immutable bundled exercise thumbnails; measure thumbnail decoding separately.
- Load only the catalog for the selected Train library section; do not publish identical plan-catalog snapshots.
- Decode display-size storage images immediately off the main actor, read local files off the main actor, and tie displayed image/error state to the complete URL/account/size request. Preserve existing private-media authorization and non-caching rules; do not cache mutable local files.
- Add recording-projection invalidation regression coverage. Physical-device traces and database query plans remain outstanding; no measured speedup is claimed.

## Third pass

- Index canonical favorite membership and per-kind counts; do not publish an unchanged favorite projection. Retain all original offline/server mutation semantics.
- Scope map preview identity to the active account, clear stale image state on route changes, and retain same-request Ghost preview state during HealthKit route refresh and keep the existing HealthKit access path.
- Fetch only the actor profile cards needed for a feed page using the existing access-controlled query; no schema or RLS changes.
- Separate Home feed and full-context freshness markers, cache successful empty pages, and check account ownership after asynchronous reads.
- No database query-plan measurement or physical-device performance validation has been performed in this pass.

## Fourth pass

- Compute one owner-local inbox projection for unread counts, latest messages and pending requests, invalidated on conversation or message mutations. No changes to the server, delivery, read receipt or deletion semantics.
- Cache strength personal-record projections until history changes; invalidate both caches on account switches and history mutations. Existing record matching rules are unchanged.
- Move static set totals and completion checks outside the live status card's one-second timeline. Timers and coach/recording logic remain unchanged.
- Added targeted inbox projection and strength history/account invalidation regression tests. Real database execution plans and physical-device profiling remain outstanding.

## Fifth pass

- Single-flight refreshes for online status, training status, visible live sessions and expired-state maintenance. Concurrent callers await the same request; failed reads do not advance freshness. Scope state to the active account and reject late responses.
- Keep existing 35/60/20-second read freshness windows and GPS/recording intervals. Physical cleanup runs at most once per successful 180-second window (the live database SELECT policies already exclude expired locations and sessions older than 12 hours). No authorization or RLS changes.
- Select only the required online presence fields and active/paused sessions.
- Read-only database audit confirms existing indexes for profile identity, online presence, message threads/unread messages, live session owner/opponent, and participant queries. The developer database is very small; sequential scans alone do not justify adding indexes. Leave unused and unique indexes intact until representative query-plan evidence is available.
- Added coalescer freshness/failure/reset tests; concurrent account transition and physical device validation remain outstanding.
